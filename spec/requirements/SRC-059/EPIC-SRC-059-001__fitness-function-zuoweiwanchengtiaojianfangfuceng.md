# EPIC-SRC-059-001: Fitness Function 作为完成条件防腐层

## 目标

构建统一的 Fitness Runner 执行器，为 LEE 工作流提供集中化的完成条件入口，通过扫描规则文件、执行命令采样、聚合多维度完成条件并产出结构化 fitness_result，解决 agent 将局部完成误判为整体完成的问题，为 Supervisor、Gate 审批者和工程治理团队提供可消费的完成证明。

## 范围

1. **提供集中化完成条件扫描与聚合入口**，使 agent 能获取全局完成信号
2. **提供 fitness_result 结构化输出格式**，包含 pass/fail 判定与多维度视图，供 Supervisor 和 Gate 审批者消费
3. **提供 hard_gate_results 与现有 Gate 语义的对接能力**，复用现有 gate 规则文件
4. **提供 dimension_results 多维度视图**，支持规则覆盖率与执行追踪
5. **提供 fitness_result 回挂到 evidence pack 的能力**，形成完整证据链
6. **明确与现有 verifier 与 completion checker 的职责边界**，避免重叠
7. **为 AI 执行器 (agent) 提供明确的完成信号执行入口**
8. **保留 Supervisor 最终独立关闭边界**，fitness_result=pass 不直接等价于 workflow completion

## 非目标

- 用 Fitness 替代人工 approval 决策
- 用 Fitness 替代需求链测试体系的全部能力
- 在本 EPIC 中冻结最终数据库 schema
- 在本 EPIC 中冻结最终 UI 控制台形态
- 一次性迁移全部历史 gate/verifier/testset 规则
- 承担阻断、升级、审批决策职责（属于 Gate 职责）
- 替代现有 Gate 的阻断与审批语义

## 成功标准

1. agent 局部测试通过误判为整体完成的误判率降低（需基线测量后设定量化目标）
2. Supervisor 审查时无需手工拼接完成条件，可直接消费 fitness_result 结构化输出
3. Gate 审批者可直接消费 hard_gate_results 作为判定输入，无需额外解析
4. 工程治理团队通过 dimension_results 获取多维度规则覆盖率与执行追踪视图
5. hard_gate 失败时 agent 无法宣布退出循环，形成有效阻断
6. evidence pack 能回挂 fitness 执行结果形成完整证据链，审阅者无需自己拼接是否闭环
7. fitness_result 可被现有 gate 语义消费，无需改造现有 gate 规则文件

## 优先级

**P0** - 高优先级，解决 AI 交付误判痛点

## FEAT 拆分原则

1. **按执行器核心能力边界拆分**：Fitness Runner 执行器核心、fitness_result 输出格式、规则扫描与采样执行分离
2. **按对接层拆分**：hard_gate_results 对接层、evidence pack 回挂层、Gate 语义消费层分别独立
3. **按维度拆分**：dimension_results 多维度视图按治理维度（规则覆盖率、执行追踪、完成证明）拆分
4. **按迁移节奏拆分**：新规则原生支持优先，历史 gate/verifier/testset 迁移作为后续迭代
5. **保持与 verifier、completion checker 边界清晰**，各自职责不重叠
