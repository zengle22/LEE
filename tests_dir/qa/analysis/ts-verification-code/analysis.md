## 2. 模块边界定义

### 2.1 模块范围 (Module Boundary)

```yaml
module: verification-code
boundaries:
  in_scope:
    - 验证码发送 API (POST /api/send-code)
    - 验证码验证 API (POST /api/verify-code)
    - 短信服务商管理（主备切换）
    - 验证码生命周期管理（生成、存储、过期、验证后失效）
    - 手机号格式验证
    - 发送频率控制（隐含）
    
  out_of_scope:
    - 用户注册流程
    - 用户密码登录
    - 第三方 OAuth 登录
    - 短信内容模板管理
    - 短信费用结算
    
  interfaces:
    upstream:
      - 用户端（移动端/前端）
    downstream:
      - 主短信服务商 API
      - 备用短信服务商 API
      - 缓存/存储服务（验证码存储）
      - 日志服务
```

## 4. 验收标准映射

### 4.1 AC-001: 验证码发送 API 正常调用

**Given**: 用户输入有效手机号

**When**: 调用 `POST /api/send-code`

**Then**:
- API 返回状态码 200 ✓
- 用户收到短信验证码 ✓
- 验证码 60 秒内有效 ✓

**映射可测试特性**: TF-001, TF-002, NF-001, SEC-001

### 4.2 AC-002: 主方案失败时自动切换备用方案

**Given**: 主短信服务商不可用

**When**: 调用验证码发送 API

**Then**:
- 自动切换到备用服务商 ✓
- 用户仍能收到验证码 ✓
- 记录切换日志 ✓

**映射可测试特性**: TF-003, TF-004, NF-004, ERR-001

### 4.3 AC-003: 验证码验证 API 正常调用

**Given**: 用户输入手机号和验证码

**When**: 调用 `POST /api/verify-code`

**Then**:
- 正确验证码返回成功 ✓
- 错误验证码返回失败 ✓
- 验证码使用后立即失效 ✓

**映射可测试特性**: TF-005, TF-006, TF-007, NF-001

## 6. 风险与依赖

### 6.1 测试风险

| 风险项 | 影响 | 缓解措施 |
|--------|------|----------|
| 外部短信服务商不稳定 | 集成测试不可靠 | 使用 Mock 服务商 + 沙箱环境 |
