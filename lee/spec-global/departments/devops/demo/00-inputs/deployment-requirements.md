# Task Manager 部署需求

> **项目**: task-manager v1.0.0
> **创建日期**: 2026-01-29
> **需求提供者**: Product Owner

---

## 1. 部署目标

### 1.1 目标环境

| 环境 | 用途 | 数据 | 审批要求 |
|------|------|------|----------|
| **dev** | 日常开发和快速验证 | 测试数据 | 无需审批 |
| **test** | QA 测试和集成验证 | 真实测试数据 | DevOps Lead 审批 |

### 1.2 部署优先级

1. **dev 环境** - 最高优先级，开发者需要快速迭代
2. **test 环境** - 中等优先级，QA 团队需要稳定测试环境

---

## 2. 技术需求

### 2.1 容器化部署

- ✅ 使用 Docker Compose
- ✅ 支持一键部署和回滚
- ✅ 健康检查机制
- ✅ 自动重启策略

### 2.2 服务依赖关系

```
nginx (反向代理)
  ↓
app (应用服务)
  ↓
db (PostgreSQL) + redis (缓存)
```

### 2.3 端口映射

| 服务 | Dev 环境端口 | Test 环境端口 |
|------|-------------|--------------|
| nginx | 8080 | 80 |
| app | 8000 | 8000 |
| db | 5432 | 5432 |
| redis | 6379 | 6379 |

## 3. 安全需求

### 3.1 凭证管理

- ❌ AI 不生成真实密钥
- ✅ 人类注入所有敏感信息
- ✅ 使用占位符模式 `${PLACEHOLDER}`

### 3.2 环境隔离

- Dev 和 Test 环境完全隔离
- 不同环境使用不同的凭证
- 数据库相互独立

### 3.3 HTTPS 要求

- Dev 环境：可选（用于本地开发）
- Test 环境：强制启用

---

## 4. 可靠性需求

### 4.1 健康检查

所有服务必须配置健康检查：
- 应用：`/health` 端点
- 数据库：`pg_isready`
- Redis：`PING` 命令
- Nginx：HTTP 200 响应

### 4.2 自动重启

- 策略：`unless-stopped`
- 失败后自动重启
- 最多重启次数：无限制

### 4.3 数据备份

- Dev 环境：每天凌晨 2 点备份
- Test 环境：每天凌晨 3 点备份
- 备份保留：7 天（dev）、14 天（test）

---

## 5. 运维需求

### 5.1 日志管理

- 日志级别：dev（debug）、test（info）
- 日志输出：控制台 + 文件
- 日志轮转：按大小（10M）

### 5.2 监控指标

- 应用指标：响应时间、错误率
- 资源指标：CPU、内存、磁盘
- 业务指标：任务创建、完成数量

### 5.3 告警配置

- 健康检查失败：立即告警
- 错误率 > 5%：告警
- 响应时间 > 1s：告警

---

## 6. 部署流程需求

### 6.1 部署前检查

- [ ] 环境配置文件已准备
- [ ] 数据库迁移脚本已准备
- [ ] 回滚脚本已准备
- [ ] 监控告警已配置

### 6.2 部署步骤

1. 停止现有服务
2. 备份当前配置
3. 拉取最新镜像
4. 启动新服务
5. 等待健康检查
6. 运行数据库迁移（如需要）
7. 验证服务可用性

### 6.3 部署后验证

- [ ] 所有服务健康检查通过
- [ ] API 响应正常
- [ ] 数据库连接正常
- [ ] 日志正常收集

---

## 7. 回滚需求

### 7.1 回滚触发条件

- 部署失败
- 健康检查失败
- 关键功能不可用
- 性能严重下降

### 7.2 回滚步骤

1. 停止当前服务
2. 恢复上一个版本
3. 启动恢复的服务
4. 验证服务可用性
5. 生成回滚报告

### 7.3 回滚时间

- 目标：< 10 分钟
- 包含数据回滚：< 30 分钟
