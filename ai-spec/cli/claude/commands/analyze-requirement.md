# 产品目标价值分析

你正在执行产品需求分析任务。

## 任务说明

根据用户提供的产品需求，进行全面的目标价值分析，生成标准化的分析报告。

## 执行步骤

### 1. 获取需求信息

$requirement

如果上面没有需求内容，请向用户询问以下信息：

- **需求标题**：简洁描述需求的名称
- **需求描述**：详细说明需求的内容、背景、期望效果
- **目标用户**：这个需求服务的用户群体
- **期望上线时间**：（可选）预期的上线时间
- **提交人**：需求的提交者
- **补充上下文**：（可选）任何有助于理解需求的背景信息

### 2. 多维度分析

从以下四个维度分析需求：

#### 用户价值 👥
- 解决什么用户痛点？
- 用户能获得什么收益？
- 影响多少用户？
- 评分：HIGH / MEDIUM / LOW

#### 行业情况 📊
- 是否符合行业趋势？
- 竞品对比如何？
- 有什么行业壁垒？
- 评分：HIGH / MEDIUM / LOW

#### 生产效率 ⚙️
- 对团队效率的影响？
- 自动化潜力如何？
- 实现复杂度？
- 评分：HIGH / MEDIUM / LOW

#### 成本管理 💰
- 开发成本预估？
- 运营成本预估？
- ROI预期如何？
- 评分：HIGH / MEDIUM / LOW

### 3. 提取核心目标

- 识别主要目标（PRIMARY）
- 识别次要目标（SECONDARY）
- 定义衡量指标和成功标准

### 4. 构建价值穿达链

建立完整链路：
```
用户需求 → 产品功能 → 直接价值 → 业务影响 → 战略意义
```

### 5. 综合评估

- 计算综合评分
- 给出优先级建议（P0/P1/P2/P3）
- 总结分析结论
- 列出下一步行动

### 6. 生成报告

使用标准模板生成Markdown报告，保存到 `output/` 目录。

报告必须包含审批区域，标注为"待审批"状态。

## 输出要求

1. 分析过程透明 - 展示你的分析思路
2. 结论有理有据 - 每个评分都要有依据
3. 报告格式规范 - 严格按照模板输出
4. 审批卡点明确 - 强调需要人工审批

## 完成后

告知用户：
1. 报告已生成的路径
2. 分析的关键结论摘要
3. 提醒需要人工审批才能进入下一环节
4. 如何使用 `/review-analysis` 进行审批
