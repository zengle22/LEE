# 产品目标价值分析指南

## 分析方法论

### 价值金字塔模型

```
          ┌─────────────┐
          │  战略价值   │  ← 长期竞争优势
          ├─────────────┤
          │  业务价值   │  ← 收入/成本/效率
          ├─────────────┤
          │  产品价值   │  ← 功能/体验
          ├─────────────┤
          │  用户价值   │  ← 解决问题/满足需求
          └─────────────┘
```

**自下而上**：从用户价值出发，逐层向上传导
**自上而下**：从战略目标分解，确保方向一致

### 价值穿达检验法

问自己三个问题：
1. **Why** - 为什么要做这个？（用户痛点）
2. **What** - 做了能带来什么？（直接价值）
3. **So What** - 对业务意味着什么？（业务影响）

如果无法清晰回答，说明价值穿达不清晰。

## 维度评分详细标准

### 用户价值评分

#### 🟢 HIGH（高）
- 解决的是用户**高频**且**强烈**的痛点
- 用户收益**可量化**且**显著**
- 影响**大规模**用户群体（>50%目标用户）
- 用户**主动**表达过此类需求

#### 🟡 MEDIUM（中）
- 解决的是用户**存在但不紧迫**的痛点
- 用户收益存在但**不够突出**
- 影响**部分**用户群体（10-50%目标用户）
- 属于**锦上添花**类需求

#### 🔴 LOW（低）
- 痛点**不明确**或**臆测**
- 用户收益**难以描述**
- 影响**少量**用户（<10%目标用户）
- **缺乏**用户调研支撑

### 行业情况评分

#### 🟢 HIGH（高）
- **顺应**明确的行业发展趋势
- 有**差异化**竞争优势
- 市场机会**明确且规模可观**
- **无**或**可控**的行业壁垒

#### 🟡 MEDIUM（中）
- 趋势**中性**，不逆势但也不顺势
- 与竞品**相当**，无明显差异
- 市场机会**存在但待验证**
- 有一定行业壁垒但**可克服**

#### 🔴 LOW（低）
- **逆**行业趋势
- **缺乏**差异化，同质化严重
- 市场机会**不明**或**萎缩**
- 行业壁垒**高**且**难以克服**

### 生产效率评分

#### 🟢 HIGH（高）
- **显著提升**团队/用户效率
- **高**自动化潜力
- 可形成**可复用**资产
- 技术方案**成熟**，风险可控

#### 🟡 MEDIUM（中）
- 效率影响**中性**
- **部分**可自动化
- 属于**标准**开发工作
- 技术方案**常规**，有一定挑战

#### 🔴 LOW（低）
- 可能**降低**短期效率
- **低**自动化潜力
- 技术**复杂度高**
- 实现周期**长**，风险大

### 成本管理评分

#### 🟢 HIGH（高）
- 开发成本**可控**且**合理**
- ROI**明确为正**
- 有**明确**的成本节约机会
- **短期**即可见效

#### 🟡 MEDIUM（中）
- 开发成本**中等**
- ROI**待验证**
- 成本影响**中性**
- **中期**见效

#### 🔴 LOW（低）
- 开发成本**高昂**
- ROI**不明**或**为负**
- 持续产生**高运营成本**
- **长期**才能见效，不确定性大

## 优先级判定矩阵

```
              用户价值
         HIGH   MEDIUM   LOW
综   HIGH   P0      P1      P2
合   MEDIUM P1      P2      P3
评   LOW    P2      P3      P3
分
```

**特殊规则**：
- 任何维度有**多个HIGH风险** → 降一级
- 涉及**安全/合规问题** → 必须优先处理
- **CEO/高管明确要求** → 另行评估

## 常见分析陷阱

### 1. 假设陷阱
❌ "用户肯定需要这个功能"
✅ 有用户调研/反馈数据支撑

### 2. 技术驱动陷阱
❌ "这个技术很酷，我们应该用"
✅ 技术选型服务于用户价值

### 3. 竞品模仿陷阱
❌ "竞品有，我们也要有"
✅ 分析是否符合我们的定位和用户需求

### 4. 沉没成本陷阱
❌ "已经投入这么多了，不能放弃"
✅ 基于当前价值评估，而非历史投入

### 5. 宏大叙事陷阱
❌ "这是未来的趋势，战略意义重大"
✅ 有具体的价值路径和可衡量指标

## 分析报告质量检查清单

### 完整性检查
- [ ] 四个维度是否都有分析？
- [ ] 每个维度是否有评分和依据？
- [ ] 是否识别了主要风险？
- [ ] 是否提出了可操作的建议？

### 逻辑性检查
- [ ] 价值穿达链是否逻辑通顺？
- [ ] 评分与分析内容是否一致？
- [ ] 优先级建议是否有据可依？

### 可操作性检查
- [ ] 核心目标是否可衡量？
- [ ] 成功标准是否明确？
- [ ] 下一步行动是否具体？

### 审批就绪检查
- [ ] 报告格式是否规范？
- [ ] 审批区域是否完整？
- [ ] 是否标注为"待审批"状态？

## 与其他环节的衔接

### 分析完成后

1. **审批环节** - 使用 `/review-analysis` 进行人工审批
2. **通过后** - 进入产品设计/技术方案环节
3. **需修订** - 根据建议修改后重新分析
4. **拒绝** - 归档并反馈给需求方

### 输出物流转

```
分析报告 (.md)
    │
    ├─→ 审批通过 ─→ 产品PRD ─→ 技术方案 ─→ 开发
    │
    ├─→ 需修订 ─→ 返回修改 ─→ 重新分析
    │
    └─→ 拒绝 ─→ 归档说明
```
