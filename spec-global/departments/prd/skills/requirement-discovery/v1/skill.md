# 需求发现能力

这是一个完整的需求发现能力模块，提供从市场调研到商业机会冻结的端到端流程。

## 冻结点概念

### 什么是冻结点

冻结点是需求发现流程中的质量门禁，确保：
- 上游分析质量达标
- 人类对关键结论显式确认
- 下游Agent基于可靠事实工作

### 两个核心冻结点

| 冻结点 | 输入 | 确认内容 | 输出 | 下游使用 |
|--------|------|----------|------|----------|
| **需求调研冻结** | 三维分析报告 | 事实准确性、假设合理性 | research-freeze.md | 商业机会分析 |
| **商业机会冻结** | 商业机会报告 | 机会评级、切入策略 | opportunity-freeze.md | 产品设计 |

### 三维分析说明

#### 维度1: 用户信号分析

**Agent**: `user-signal-analyzer`

**核心问题**: 搜索这个词的人，试图解决什么问题？

**分析内容**:
- 用户画像推断（谁+场景）
- 搜索意图分析（信息型/工具型/交易前型/导航型）
- 痛点强度评估（频率/紧急性/失败成本）
- JTBD框架应用

**输出**: 用户信号分析报告 → `output/user-signals/`

#### 维度2: 行业结构分析

**Agent**: `industry-structure-analyzer`

**核心问题**: 这个问题所在的行业，处于什么阶段？

**分析内容**:
- 行业成熟度（新兴 / 成长期 / 内卷）
- 瓶颈识别（技术瓶颈 or 供给侧瓶颈）
- 结构性空位（是否存在系统性机会）

**输出**: 行业结构分析报告 → `output/industry-structure/`

#### 维度3: 竞品供给分析

**Agent**: `supply-analyzer`

**核心问题**: 已有解决方案哪里不够好？

**分析内容**:
- Existing Solutions（现有方案分类）
- Gaps（明显不足）
  - Unserved Segment（被忽视的细分）
  - Poor UX（用户体验差）
  - High Cost（成本过高）
  - Poor Integration（集成差）

**输出**: 竞品供给分析报告 → 项目根目录

### 商业机会评估维度

| 维度 | 评分范围 | 说明 |
|------|----------|------|
| 市场空白度 | 0-100 | 是否存在被忽视的细分市场？ |
| 进入门槛 | 0-100 | 分数越高门槛越低，越容易进入 |
| 差异化潜力 | 0-100 | 能否通过创新形成差异化？ |
| 小团队适配度 | 0-100 | 是否适合1-10人规模团队？ |

### 综合评级标准

| 评级 | 条件 | 建议 |
|------|------|------|
| **A级** | 四维度均分≥80 | 强烈推荐，立即切入 |
| **B级** | 四维度均分≥65 | 推荐，需关注短板 |
| **C级** | 四维度均分≥50 | 谨慎，需进一步验证 |
| **D级** | 四维度均分<50 | 不推荐，放弃或重新定位 |

## 错误处理

### 前置条件不满足

```
❌ 无法执行需求调研冻结

原因: 缺少必要的分析报告
- 用户信号分析: ❌ 缺失
- 行业结构分析: ⚠️ 未找到
- 竞品供给分析: ✅ 存在

请先运行以下命令:
  /analyze-user-signal    # 生成用户信号分析
  /analyze-industry       # 生成行业结构分析
```

### 人类拒绝确认

```
⚠️ 冻结被拒绝

确认点 2/4 (行业结构分析) 被拒绝
拒绝原因: "市场阶段判断有误，应该是成长期而非成熟期"

下一步:
1. 重新运行 /analyze-industry 更新分析
2. 或手动修改后重新请求确认
3. 运行 /freeze-research 重新评审
```

## 最佳实践

1. **完整执行流程**: 不要跳过任何一个分析步骤
2. **及时确认**: 生成冻结方案后尽快请求人类确认
3. **记录原因**: 人类确认/拒绝时记录具体原因
4. **版本控制**: 每次冻结生成唯一ID，便于追溯
5. **增量更新**: 如需更新已冻结内容，重新走完整流程
