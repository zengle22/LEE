# OpenSpec Integration Points

本文档描述 OpenSpec 如何集成到 Development Pipeline 中作为 Phase 级子流程。

## 核心理念

```
OpenSpec = Phase 级"临时但可追溯的工作空间"
         ≠ 项目级方法论
         ≠ 长期知识库

每个 Phase 独立实例化一个 OpenSpec 工作空间
通过 phase.yaml 定义输入边界
通过 handover.yaml 输出到主流程
```

## 集成架构

```
L0: Development Pipeline (主流程)
    │
    ├── Phase Planning
    │
    └── Phase Execution ─────┐
          │                  │
          ▼                  ▼
    L1: Phase OpenSpec Flow (OpenSpec 子流程)
          │
          ├── Init ─────────────── openspec init {change-id}
          ├── Calibration ──────── 需求校准
          ├── Test Contract ────── 测试契约生成
          ├── Proposal ─────────── openspec propose {change-id}
          ├── Implementation ───── 代码实现
          ├── Unit Test ────────── 单元测试
          ├── Review ───────────── openspec review {change-id}
          ├── Retrospective ────── Phase 复盘
          └── Archive ──────────── openspec archive {change-id}
```

## OpenSpec CLI 集成点

### 1. Phase 初始化

```bash
# 在 Phase 目录下初始化 OpenSpec 工作空间
cd 04-phases/{phase-id}
openspec init {change-id}
```

**产出目录结构:**
```
openspec/
├── changes/
│   └── {change-id}/
│       ├── proposal.md
│       ├── tasks.md
│       └── design.md (optional)
└── specs/
    └── {capability}/
        └── spec.md
```

### 2. 创建变更提案

```bash
# 基于校准后的需求创建提案
openspec propose {change-id}

# 生成文件:
# - changes/{change-id}/proposal.md
# - changes/{change-id}/tasks.md
# - specs/{capability}/spec.md (delta)
```

**关键规则:**
- Scenarios 必须使用 `#### Scenario:` 格式 (4 hashtags)
- 每个 Requirement 必须使用 `### Requirement:` 格式 (3 hashtags)
- 每个 Requirement 至少有一个 Scenario

### 3. 验证提案

```bash
# 验证提案格式和完整性
openspec validate {change-id} --strict

# 检查项:
# - proposal.md 包含 Why/What/Impact
# - tasks.md 有可执行检查清单
# - 每个 requirement 有至少一个 scenario
# - scenario 格式正确 (GIVEN/WHEN/THEN)
```

### 4. Code Review

```bash
# 触发代码审查
openspec review {change-id}

# 产出:
# - 04-review/review-report.md
# - 04-review/review-summary.json
```

### 5. 归档变更

```bash
# Phase 完成后归档
openspec archive {change-id}

# 归档内容:
# - 最终的 spec deltas
# - review 记录
# - 复盘知识 (patterns/anti-patterns)
```

## Phase Contract 边界

Phase Contract (`phase.yaml`) 定义了主流程与 OpenSpec 子流程的边界:

```yaml
# phase.yaml 示例
phase_id: auth-login
version: 1.0

inputs:
  requirements:
    source: "02-requirements/prd.md"
    sections: ["用户认证"]
  ui:
    source: "01-ui/ui-freeze/"
  architecture:
    source: "02-requirements/architecture.md"

outputs:
  deliverables:
    - "src/features/auth/**"
  interfaces:
    - endpoint: "/api/auth/login"
      method: POST
  test_coverage:
    threshold: 80

openspec:
  change_id: "add-user-auth"
  workspace: "./openspec/"
```

## 错误处理

### OpenSpec 验证失败

```
if openspec validate {change-id} fails:
    1. 获取详细错误信息
    2. 通知 OpenSpec Proposal Creator Agent 修复
    3. 重新验证
    4. 最多重试 3 次
    5. 超过重试次数则人工介入
```

### Review 未通过

```
if review status != "approved":
    1. 解析 review 问题列表
    2. 创建修复任务
    3. 实现修复
    4. 重新提交 review
    5. 循环直到通过或人工介入
```
