## 新增技术债务 (不影响当前上线)

### 🟡 TD-L2V3-101: L2 v3 模板未集成到 Orchestrator 主流程

**严重程度**: Medium | **优先级**: P2 | **类别**: Architecture

**描述**:
L2 v3 工作流模板已创建，但 Orchestrator 的 `WorkflowLoader` 尚未更新以识别和加载 v3 模板。

**影响**:
- 无法通过 CLI 直接创建 L2 v3 实例
- v3 特性（kind, complexity, spawns_l3）不会被解析

**修复建议**:
1. 更新 `WorkflowLoader` 支持 `kind` 字段识别
2. 添加 `complexity` 和 `spawns_l3` 字段解析
3. 更新 CLI 命令 `lee workflow create` 支持 `--version v3` 参数

**预计工作量**: 8 小时

**相关文件**:
- `src/lee/orchestrator/execution/template_manager.py`
- `src/lee/orchestrator/cli/main.py`

### 🟡 TD-L2V3-102: L3 v3 模板路径硬编码

**严重程度**: Low | **优先级**: P2 | **类别**: Code Quality

**描述**:
`_spawn_l3_for_point` 方法中 L3 v3 模板路径是硬编码的相对路径：

1. 将模板路径配置化（加入 config/llm_config.yaml）
2. 支持环境变量 `L3_V3_TEMPLATE_PATH`
3. 添加 fallback 逻辑（v3 → v2 → default）

**预计工作量**: 4 小时

### 🟢 TD-L2V3-103: L3 v3 6步流程未实现执行逻辑

**严重程度**: Low | **优先级**: P3 | **类别**: Feature

**描述**:
L3 v3 模板定义了 6 个步骤（align_requirement, design_tests, implement, run_tests, code_review, retrospective），但这些步骤的具体执行逻辑尚未实现。

**影响**:
- L3 v3 实例可以创建，但执行时会跳过未实现的步骤
- 6步 TDD 流程的完整价值无法体现

**修复建议**:
1. 为每个步骤实现对应的 Skill 或 Agent
2. align_requirement: 使用 PRD 分析 Agent
3. design_tests: 调用 QA workflow 的测试用例设计
4. implement: 使用现有代码生成能力
5. run_tests: 集成测试运行器
6. code_review: 实现代码评审 Agent
7. retrospective: 实现复盘总结 Agent

**预计工作量**: 40 小时

---

### 🟢 TD-L2V3-104: Complexity=L 的 PMA 拆分未实现

**严重程度**: Low | **优先级**: P3 | **类别**: Feature

**描述**:
L2 v3 支持 complexity=L 级别，该级别应该使用 PM Agent 将大型功能拆分成多个功能点，每个功能点 spawn 一个 L3。但 PMA 拆分逻辑尚未实现。

**影响**:
- complexity=L 的阶段会降级到直接执行
- 大型功能无法自动化拆分和并行开发

**修复建议**:
1. 集成 PM Agent workflow
2. 实现 `_split_phase_with_pma` 方法
3. 拆分结果生成多个 Point，每个 Point spawn 一个 L3
4. 支持 L3 实例间的依赖关系管理

**预计工作量**: 32 小时

**严重程度**: Low | **优先级**: P3 | **类别**: Feature

3. 统计已 spawn 的 L3 实例及其状态
4. 计算整体进度百分比

### 🟢 TD-L2V3-106: 事件总线发布逻辑不完整

**严重程度**: Low | **优先级**: P3 | **类别**: Architecture

**描述**:
虽然添加了 `L3_SPAWNED` 事件发布，但以下事件尚未发布：
- `L2_PHASE_STARTED` (阶段开始)
- `L2_PHASE_COMPLETED` (阶段完成)
- `PMA_SPLIT_COMPLETED` (PMA 拆分完成)
- `L3_COMPLETED` (L3 完成，需要在 L2 层监听)

**影响**:
- 无法构建完整的 L2/L3 事件追踪链路
- 外部监听器无法获取完整的执行状态变化

**修复建议**:
1. 在 Phase 执行开始时发布 `L2_PHASE_STARTED`
2. 在 Phase 执行完成时发布 `L2_PHASE_COMPLETED`
3. 在 PMA 拆分完成后发布 `PMA_SPLIT_COMPLETED`
4. 添加 `L3_COMPLETED` 事件监听器，更新 L2 状态

**预计工作量**: 12 小时

### 🟢 TD-L2V3-107: 阶段并行执行未实现

**严重程度**: Low | **优先级**: P3 | **类别**: Feature

**描述**:
L2 v3 支持通过 `depends_on` 定义阶段依赖，理论上可支持并行执行。但当前 Orchestrator 仍然是顺序执行阶段。

**影响**:
- 即使阶段间无依赖，也会串行执行
- 无法利用并行能力提升效率

**修复建议**:
1. 实现 DAG 拓扑排序算法
2. 识别可并行执行的阶段集合
3. 使用 asyncio.create_task 并行执行
4. 处理并行阶段的错误传播

**预计工作量**: 24 小时
