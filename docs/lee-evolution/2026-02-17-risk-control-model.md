# LEE 2.0 风险控制模型（未来演进北极星版）

## 一、LEE 2.0 风险控制整体模型

```
                          ┌────────────────────────┐
                          │        L1 人类层        │
                          │  战略签字 / 上线签字    │
                          │  风险预算 / 接管决策    │
                          └────────────┬───────────┘
                                       │
                          ┌────────────▼───────────┐
                          │     风险与健康雷达层    │
                          │  (Risk & Health Layer)  │
                          │                        │
                          │  ▸ 漂移监控            │
                          │  ▸ 风险分级            │
                          │  ▸ 预警机制            │
                          │  ▸ 自动纠偏触发        │
                          └────────────┬───────────┘
                                       │
                          ┌────────────▼───────────┐
                          │       L2 治理层         │
                          │  Gate / Budget / Policy │
                          │                        │
                          │  ▸ 完成门禁            │
                          │  ▸ 风险预算            │
                          │  ▸ allow/ask/deny      │
                          └────────────┬───────────┘
                                       │
                          ┌────────────▼───────────┐
                          │       L3 执行层         │
                          │  LLM Planner + Tools   │
                          │                        │
                          │  ▸ 自动规划            │
                          │  ▸ 编码/测试/修复      │
                          │  ▸ 重试循环            │
                          └────────────────────────┘
```

**核心思想：**

- **L3** 负责“跑”
- **L2** 负责“约束”
- **Risk Layer** 负责“盯趋势”
- **L1** 负责“最终责任”

## 二、风险控制的动态闭环

```
       ┌───────────────┐
       │   执行任务    │
       └──────┬────────┘
              │
              ▼
       ┌───────────────┐
       │  产生运行信号 │
       │  (metrics/log)│
       └──────┬────────┘
              │
              ▼
       ┌────────────────┐
       │  风险雷达计算器 │
       │   Risk Index   │
       └──────┬─────────┘
              │
      ┌───────┼───────────────┐
      │       │               │
      ▼       ▼               ▼
   Green    Yellow         Orange/Red
   正常     提醒           触发干预
                          │
                          ▼
               ┌──────────────────┐
               │  自动纠偏 / ask  │
               └──────────────────┘
```

**重点：**

- 风险不是等到“最终签字”才暴露
- 风险在运行中被连续计算

## 三、风险指数（Risk Index）模型

未来你可以有一个统一风险指数 **R**，不是拍脑袋，而是多信号加权：

```
R = w1*目标漂移
  + w2*复杂度异常
  + w3*质量下降
  + w4*时间偏离
  + w5*重试频率
```

**信号量化示例：**

| 信号 | 阈值 | 权重 |
|------|------|------|
| 连续重试次数 | > 3 | +1 |
| 测试通过率下降 | 5% | +2 |
| 计划被重写 | 2次以上 | +1 |
| 新增风险未关闭 | - | +1 |
| 超出风险预算 | - | +3 |

**风险分级：**

| R 值 | 等级 | 状态 |
|------|------|------|
| R < 3 | Green | 正常 |
| 3 ≤ R < 6 | Yellow | 提醒 |
| 6 ≤ R < 9 | Orange | 干预 |
| ≥ 9 | Red | 强制停止 |

这就是**“系统带伤但可控”**的量化基础。

## 四、三层干预策略模型

当风险升高时，不是立刻人工接管，而是分级干预：

### ① 软纠偏（Soft Correction）

- LLM 反思子流程
- 自动调整计划
- 提示范围收缩
- 提示拆分任务
- **系统自我修复**

### ② 受控暂停（Controlled Pause）

- 暂停当前 workflow
- 请求人工确认
- 或请求 L2 决策
- **这是 Orange 区间**

### ③ 强制门禁（Hard Gate）

- 超出风险预算
- 禁止继续
- **必须人类接管**
- **这是 Red 区间**

## 五、健康维度模型（工程视角）

风险不是单一维度，未来有四个健康面板：

| 健康维度 | 描述 |
|----------|------|
| Goal Health | 目标健康度 |
| Quality Health | 质量健康度 |
| Complexity Health | 复杂度健康度 |
| Time Health | 进度健康度 |

**人类 L1 看的是：**

- 当前风险指数
- 四个健康条
- 当前是否可签字

**不看具体代码。**

## 六、风险预算机制（Risk Budget）

每个项目在开工签时定义：

| 预算项 | 描述 |
|--------|------|
| 最大可接受 R | 风险上限 |
| 最大重试次数 | 尝试上限 |
| 最大已知缺陷数 | 缺陷容忍度 |
| 最低测试覆盖率 | 质量底线 |

**触发条件：** 一旦突破预算 → 自动触发 ask

**效果：**

- 风险可接受范围内自动运行
- 超界必须人类承担决策

---

## 七、为什么这套模型成熟？

它解决了三件事：

1. **不幻想“无风险”** — 承认风险存在
2. **不靠感觉判断是否失控** — 量化风险指数
3. **不把人类变成流程阻塞者** — 只在关键节点介入

**人类只在两种情况下出现：**

- 风险突破预算
- 版本发布签字

**其余时间系统自己跑。**

---

## 八、和群友路线的本质差别

| 维度 | 群友路线 | LEE 风险路线 |
|------|----------|--------------|
| 核心 | LLM 决策为中心 | 风险指数为中心 |
| 兜底 | 工程容错 | 治理容错 |
| 定位 | 自动化 | **可计算风险的自动化** |

**这是更高级的一层。**

---

## 九、最终形态一句话

**LEE 2.0 是一个“可计算风险”的自动化系统，而不是一个“盲信 LLM”的自动化系统。**
