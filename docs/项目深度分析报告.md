## 一、项目概述

**LEE (Lightweight Execution Engine)** 是一个通用的 AI 工作流编排系统，用于管理和执行复杂的 AI Agent 工作流。

## 三、主要功能与流程

### 3.1 核心执行流程

```
用户输入 (CLI/API)
    ↓
Orchestrator.create_workflow()
    ↓
StateMachine 初始化状态
    ↓
while 有 ready steps:
    step = get_ready_step()
    ↓
    executor = ExecutorFactory.get(step.type)
    ↓
    result = await executor.execute(input_data)
    ↓
    StateMachine.update_state(result)
    ↓
    if 需要 gate 审批:
        → HumanGate 等待
    ↓
    检查是否需要 spawn 子workflow
    ↓
Workflow 完成/失败
```

### 3.2 CLI 命令

## 五、主要 Bug 与改进点

| BUG-2026-0001 | 登录页偶发 500 错误 | P1 |

### 5.2 架构层面问题

1. **执行器路径问题**: 存在两套执行器 (`orchestrator/execution/` 和 `runtime/executor/`) 可能导致混淆
2. **工作流格式兼容性**: Orchestrator 原生格式与 spec-global 企业级格式存在兼容性问题
3. **测试覆盖不完整**: 部分测试无法通过 (test_execution.py)

### 5.3 改进建议

#### 短期改进 (1-2周)
1. 集成 ContractDiscovery 到 Orchestrator 主流程
2. 完善 Gate 审批下游步骤解锁逻辑
3. 实现 Agent 规范缓存

#### 中期改进 (1个月)
1. 实现并行执行调度
2. 添加可视化追踪 UI (Jaeger/Zipkin 集成)
3. 实现事件日志分片机制

#### 长期改进 (季度)
1. 开发独立的工具代理层 (Tool Proxy)
2. 完善测试覆盖 (端到端集成测试)
3. 契约版本管理和依赖关系可视化
