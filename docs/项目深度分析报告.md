## 三、主要功能与流程

### 3.1 核心执行流程

```
用户输入 (CLI/API)
    ↓
Orchestrator.create_workflow()
    ↓
StateMachine 初始化状态
    ↓
while 有 ready steps:
    step = get_ready_step()
    ↓
    executor = ExecutorFactory.get(step.type)
    ↓
    result = await executor.execute(input_data)
    ↓
    StateMachine.update_state(result)
    ↓
    if 需要 gate 审批:
        → HumanGate 等待
    ↓
    检查是否需要 spawn 子workflow
    ↓
Workflow 完成/失败
```

### 3.4 Skill 三分法

Agent spec 中对 Skill 的引用分三类：

| agent.yaml 字段 | 类型 | 含义 | 校验规则 |
|:---:|:---:|------|------|
| `tools:` | Tool Skill | 有 runtime 的可执行 skill | **E002** 必须存在对应 spec |
| `specs:` | Spec Skill | 纯规范 skill（无 runtime） | **E003** 必须存在对应 spec |
| `capabilities:` | Capability | 自然语言能力描述 | 不校验，供 LLM 参考 |

Pre-commit hook 自动执行 `spec_validate.py` 校验。

## 五、架构层面问题与改进

### 5.1 架构问题

1. **执行器双路径**: 存在两套执行器 (`orchestrator/execution/` 和 `runtime/executor/`)，职责划分不够清晰，可能导致混淆
2. **工作流格式兼容性**: Orchestrator 原生格式与 spec-global 企业级格式存在兼容性问题
3. **orchestrator.py 体积过大**: 58K / 1645 行，承担 8 大职责，建议拆分

### 5.2 改进路线图

#### 短期改进 (1-2 周)
1. 集成 ContractDiscovery 到 Orchestrator 主流程
2. 完善 Gate 审批下游步骤解锁逻辑
3. 在 executor 调用链中启用 ToolGuard
4. 实现 Agent 规范 LRU 缓存

#### 中期改进 (1 个月)
1. 明确执行器双路径职责（文档化 + 重构）
2. 实现并行执行调度
3. 统一错误重试到 base executor
4. 拆分 orchestrator.py

#### 长期改进 (季度)
1. 事件日志分片机制
2. OpenTelemetry Span 追踪可视化
3. 契约版本管理和依赖关系可视化
